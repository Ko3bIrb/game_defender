# Правила работы с game_defender

- Изменения игры готовить в отдельной ветке и PR. Не коммитить и не отправлять изменения напрямую в `main`.
- До слияния предоставить пользователю рабочий предварительный просмотр и дождаться явного одобрения результата. PR до этого оставлять черновиком.
- При одобренном слиянии использовать Squash and merge: один итоговый коммит на логическое изменение. Не переписывать существующую историю `main` без отдельного согласования точных коммитов.
- Названия новых коммитов писать по-русски с одним из префиксов: `Сделано: ...`, `Переделано: ...` или `Изменено: ...`. Это правило распространяется и на итоговый squash-коммит в `main`.
- Скриншоты, временные файлы и промежуточные результаты проверок хранить вне исходников игры. Добавлять постоянные отчёты только при необходимости.
- Для запуска игры использовать локальные копии зафиксированных библиотек с лицензией; не возвращать обязательную загрузку Three.js с внешнего CDN.
